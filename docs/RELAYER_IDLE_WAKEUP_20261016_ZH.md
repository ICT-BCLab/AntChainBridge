# 证明完成后的 AM 唤醒与有界空闲重查

证明等待超过空闲阈值时，AM 原本只能等每256次调度的兜底扫描，造成随机几十秒等待。修复在证明事务成功提交后唤醒源链AM扫描，并将所有空闲队列的兜底改为单调时钟计时。

- **事务边界**：只在AUTH_MSG且AM为PROVED时注册afterCommit；校验异常、未就绪/拒绝或提交失败不唤醒。Redis唤醒失败只记录告警，已提交证明不重新验证，由有界扫描恢复。
- **兜底范围**：UCP、AM处理、提交、归档及Oracle队列分别按链维护原子探测标记；首次空闲立即扫描，之后`relayer.blockchain.idle.rescan_interval_ms`默认1000ms。原空闲阈值仍为10000ms，正常流量条件不变。实际响应还取决于调度间隔和服务可用性，不能把1000ms写成业务硬SLA。
- **原规则保留**：数据库查询中的证明/信任等级、失败次数、监管决策、序号分配和最终性条件均未改变。没有补发历史消息或强写其状态。
- **验证**：在生产Java8与原包全部依赖的隔离classpath运行首批10项JUnit回归；原运行类5项失败，候选类10项通过。补充20秒慢证明与真实空闲门的组合测试后，生产依赖隔离11项通过，本地Java8 Maven相关24项通过，包含成功提交、回滚、提交失败、拒绝/未就绪、缓存失效、稀疏调度、多队列及并发探测。新类字节码major52。
- **构建边界**：本机Maven首次构建遇到缓存IPTCService为旧3参签名、源码调用4参的既存快照冲突；从当前仓库重建并安装antchain-bridge-ptc后恢复，相关24项回归通过，没有改接口凑过编译。部署候选直接对运行包依赖编译这两份源码，逐项比较仅改变4个白名单class，避免替换线上其它专属修复。
- **运维**：部署、原包SHA256、备份路径、进程与上线后证据由集成工作区的OPERATIONS_LOG.md及操作交付报告记录；出现问题恢复本组件原JAR，保留原配置及全部业务数据。
